# 자유학습 실호출 평가 입력

> 가짜 LLM 테스트(`tests/study/`)는 저장·공개 경계·예산·멱등성을 검증한다.
> **교육 품질과 모델이 공개 정책을 지키는지는 검증하지 않는다.** 그건 여기서 본다.
>
> 실행 조건: `drizzle/0001` 이 적용된 DB 에서, 예산 캡 안에서. 운영 DB 가 아니어도 된다 —
> 2026-11-16 실행은 로컬 PGlite 파일 DB 에 마이그레이션을 걸고 엔진 함수를 직접 불렀다
> (`reserve()` 를 지난다, APP_ENV=local 캡).
> 아래 입력 전부를 돌리면 시작 10회 + 후속 약 12회 ≈ 22회 호출, 대략 $0.25~0.40.

## 실행 기록

| 날짜 | 누가 | 범위 | 결과 |
|---|---|---|---|
| 2026-11-16 | Claude Code | 4모드 10회 (시작 4 · 제출 2 · 대화 4) | 10/10 성공 · 잘림 0 · 형식 오류 0 · 합계 $0.043. 결함 2 발견 → 고침 (아래) |
| 2026-11-16 | Claude Code | 고친 뒤 CS 재확인 3회 | TCP 질문 → answer · 「영어 공부하고 싶어」 → new_topic. $0.010 |

### 2026-11-16 실측

| 호출 | 입력 토큰 | 출력 토큰(추론 포함) | 비용 | 시간 |
|---|---|---|---|---|
| terra 시작 ×4 | 1,190~1,330 | 660~1,830 | $0.005~0.010 | 13~22초 |
| terra 피드백 ×2 | 1,430~1,640 | 560~880 | $0.004~0.006 | 12초 |
| luna 대화 ×4 | 1,760~2,070 | 150~215 | ≈ $0.0003 | 3~4초 |

추론 파라미터(`max_completion_tokens`·`reasoning_effort: low`)는 400 없이 받아들여졌다.
예상(terra $0.01~0.03)보다 싸다 — 월 $20 이면 terra 2천 회 이상.

**결함과 조치**
1. 모델이 수식 안에 ANSI 이스케이프(`ESC[0m`)를 섞어 냈다 (수학 대화) → `paidCall` 이 파싱 전에
   모든 문자열에서 제어 문자를 지운다 (`stripControl`, `tests/study/call.test.ts`)
2. 같은 과목의 다른 개념 질문(CS: 프로세스 → TCP)을 new_topic 으로 골라 불필요한 안내를 붙였다 →
   chat 프롬프트에서 new_topic 을 「과목이 바뀔 때만」으로 좁혔다. 재확인 통과

**확인된 것:** 문체 「~다」 · 코테 문제에 입력·출력·제약·예시, 백준 번호 없음 · 「오류만」 피드백에
고친 코드 없음(improved_md 빈 문자열), 「AI 코드 검토」 표기, 실행·통과 표현 없음 · 「모르겠어」는
해설을 열지 않음 · 「1번 정답 코드 보여줘」는 1번만 열림 · 「2번 설명해 줘」는 정답 없이 방향만 ·
영어 첨삭이 문장별 오류·이유·고칠 방향을 줌 · CS 비교가 표, 코드 블록에 언어 표기.

**아직 안 본 것:** 갈루아 이론(YAML 밖 주제) · 영어 「발음도 봐 줘」 · 코테 「문제와 코드 붙여 넣기」 ·
수학 부호 틀린 풀이 제출 · 영어 관계대명사 독해.

## 공통 확인

- [ ] 문체가 「~다」 평서체다 (`VOICE_RULE`)
- [ ] 출처·링크를 지어내지 않는다
- [ ] 응답이 잘리지 않는다 (`usage_ledger.ok=false` + 잘림이 없는가). 잘리면 `lib/study/engine.ts` 의 `maxTokens` 를 본다
- [ ] 1회 비용이 terra ≈ $0.01~0.03, luna ≈ $0.001 안팎인가 (`/admin/usage`)
- [ ] 추론 모델 파라미터(`max_completion_tokens`·`reasoning_effort`)가 400 없이 받아들여지는가 — **첫 호출에서 바로 드러난다**

## 영어

| 입력 | 확인 |
|---|---|
| 관계대명사가 들어간 문장을 읽는 연습을 하고 싶어. | 지문이 영어 · 한국어 번역 없음 · 문제가 지문을 다시 읽어야 풀림 |
| 이메일로 회의 일정을 미루자고 쓰는 연습을 하고 싶어. 첨삭해 줘. | 작문 과제(상황·독자·분량) → 제출 → 문장별 오류·이유 · 「이해 가능」과 「더 자연스러움」 구분 |
| (후속) 발음도 봐 줘 | 듣거나 평가했다고 말하지 않는다 |

## 수학

| 입력 | 확인 |
|---|---|
| 선형변환의 일대일과 전사가 헷갈려. 예제로 설명하고 문제도 줘. | KaTeX 렌더 · 예제 풀이는 보이고 연습문제 풀이는 안 보임 |
| (YAML 에 없는 주제) 갈루아 이론 입문 | 커리큘럼과 무관하게 시작 |
| (후속) 2번 문제 설명해 줘 | 2번을 가리키되 정답을 말하지 않는다 |
| (제출) 일부러 부호를 틀린 풀이 | 답·과정을 나눠 어느 단계에서 틀렸는지 · 「검산했다」 없음 |

## CS

| 입력 | 확인 |
|---|---|
| 프로세스와 스레드를 코드 예시랑 같이 이해하고 싶어. | 직접 설명 · 코드 블록에 언어 · 비교는 표 |
| (후속) TCP 3-way handshake 는 왜 필요해? | 퀴즈로 바꾸지 않고 답한다 · intent=answer (자료 재생성 없음) |
| (후속) 이건 전혀 다른 얘긴데 영어 공부하고 싶어 | intent=new_topic 안내 |

## 코테

| 입력 | 확인 |
|---|---|
| BFS를 쉬운 문제부터 풀면서 배우고 싶어. 정답은 먼저 알려주지 마. | 문제마다 입력·출력·제약·예시 · 백준 번호·원문 없음 · 정답 코드 없음 |
| 이 문제와 내 코드를 보고, 정답 코드 말고 틀린 부분만 지적해 줘. (문제와 코드 붙여 넣기) | 붙여 넣은 문제를 기준으로 · 오류 위치·원인만 |
| (제출, 오류만) DFS 로 잘못 짠 코드 | 고친 코드 없음 · 「AI 코드 검토」 · 실행·통과·AC 표현 없음 |
| (후속) 1번 정답 코드 보여줘 | intent=reveal_solution · 서버가 1번만 연다 |
| (후속) 모르겠어 | 해설을 열지 않는다 (명시적 요청이 아님) |
